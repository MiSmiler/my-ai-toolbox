# Tickets

这个 repo 装的是开发过程中的 Ticket，是临时的 —— **一个目录 = 一条工作线 = 一个分支**，工作线做完，整个目录删掉。所以长期存在的东西各自说明自己：代码注释、ADR、`CONTEXT.md` 不必靠 Ticket 才读得懂，也就不引用这里。

## 结构

- 目录里全是 **Ticket**，文件名以两位编号开头。
- `00-*.md` 是 **main ticket**：这条工作线为什么存在、要做成什么，加下面的一览。它是唯一看着全局的那篇。
- `01-*.md` 起是 **sub ticket**：一件件具体的事，可以是主线的步骤，也可以是旁生的关注点。
- 反过来，**sub ticket 不挡 main ticket** —— main ticket 不必等它们做完。
- 编号按打算做的顺序发（`01`、`02`、`01d` —— 插队用字母）；**落过或弃过的编号不复用**；一览按同一个顺序排。

## 一篇 Ticket

**一件事，一个 commit。** 写多少由这一篇多大、要不要跨会话接力决定：够下一个会话接着做就行，够了就别多写。一般写的是这一篇要做成什么、条目、要小心的边界、怎么验证。

条目分两节，`## 主线` 和 `## 支线`。`## 主线` 里的内容分**待定**与**定稿**两种状态。

**待定**写成条目，收在 `### 待定` 小节里：

```md
## 主线

### 待定

- 用户 id 是自增整数还是 UUID
- 注销之后账号保留多久
```

**定稿**写成小节，一个主题一节 —— 下一个会话在这里读到定成了什么：

```md
## 主线

### 用户 id

用户 id 是 UUID。

### 待定

- 注销之后账号保留多久
```

一条从待定变成定稿，就从 `### 待定` 挪进它自己的小节。

勾（`[x]`）只活在 `## 支线` 与 main ticket 一览这两处。

`## 支线` 保持条目式：

```md
## 支线

- [ ] `UserCache` 可能需要换个名字（它装的其实是未登录访客）
- [x] (移出 → `07`) 超时的时候列表停在 loading
```

- 移出去的支线条目写上去处。
- 聊着聊着冒出来的支线条目先落进 `## 支线`，不打断当下那条主线；主线处理完再回头收支线：这一篇里能做的就一起做，超出的移给别的 Ticket 或开一张新的 sub ticket。

**为什么这样、被否掉的选项**跟结论写在一起 —— 这是下一个会话不必重新发明的原因。

## main ticket（00）

比别的 Ticket 多两节。

`## 背景和目标`：这条工作线为什么存在、要做成什么。

`## Ticket 一览`：一行一个 Ticket，顺序就是打算做的顺序。

```md
- [ ] `07` · 列表页的 loading 与空态
- [x] `05` · 按钮跟着权限走
- [x] (放弃) `02` · 列表变化实时推送
```

三个记号：`- [ ]` 没落、`- [x]` 落了、`- [x] (放弃)` 不做了。**Ticket 的落与弃只记在这里。**

main ticket 不会单独关掉：它随整个目录一起消失。

## 从开工到关掉

1. **开工**：讨论定下这一篇的范围与做法。要跨会话接力，就把接口形状用代码块写进这篇；够小就不必 —— 在对话里对齐即可。
2. **关掉**：实现已在主 repo 落成 commit；这边删掉这篇 sub ticket，并把它在 main ticket 一览里的那一行打勾 —— 同一个 commit。
3. **放弃**：把它在 main ticket 一览里的那一行写成 `- [x] (放弃)`，这篇 sub ticket 删掉。

## 各有其家

- 长期决策去 `docs/adr/`（或该 context 自己的 `docs/adr/`），领域词汇去 `CONTEXT.md`；它们与实现同一个 commit。
- 引用代码写成"文件 + 符号名"，行号会漂。
